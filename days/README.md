# How to read a day

A day is a hub plus one document. That is the whole shape.

```
days/day-NN-<slug>/
├── LESSON.md      the hub — orients and assembles. It never teaches.
├── CHECKLIST.md   the definition of done
├── parts/01-*.md  THE TEACHING — one idea, one document
└── audio/         your recordings. Yours. Gitignored.
```

Read in this order: **hub → part → back to the hub to close.**

## The seven sections of a part

1. **The one-line answer** — what it is, before any explanation
2. **The model** — what a fluent speaker actually does, plus the day's phrases
3. **Say it now** — the scripted drill
4. **Say it yours** — the unscripted rep, recorder on
5. **The deliberate failure** — the rep built to break
6. **When it breaks in the wild** — where it collapses, and the repair
7. **Check yourself** — the recorded proof

Three of the seven are you speaking. If you finish a day having read all seven and spoken in
none, the day did not happen — regardless of how well you understood it.

## Two rules that will feel wrong at first

**No clocks in here.** Duration lives in plan §4 and nowhere else. A day that runs long runs
long; nothing gets cut to fit.

**Re-recording is normal.** If **Check yourself** fails, run the drill again and re-record. That
is the process working, not a failed day. Log it in `PROGRESS.md` anyway.
